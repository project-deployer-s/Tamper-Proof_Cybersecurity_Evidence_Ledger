Attack Demonstrations

Run safe, isolated attack simulations and follow the attack, detection checks, and evidence-integrity result step by step.

Isolated simulation environment

These demonstrations use temporary sample data. They do not attack real systems, modify user messages, revoke real keys, or change the permanent evidence ledger. A demo evidence ID is not a permanent ledger record.

01

Message Tampering

See what happens when someone changes a signed message after it was created.

You will prepare a signed message, manually alter it, submit it, and run each security check yourself.

No attack is performed until you edit and submit the message.

02

Forged Digital Signature

See why a signature made with an unrelated private key cannot prove the sender's identity.

Follow the investigation manually: inspect Alice's original signature, create a signature with an unrelated key, submit it, and run identity verification yourself.

This creates temporary demo keys only. No attack or verification happens automatically.

03

Replay Attack

See how the system detects a previously used message nonce being submitted again.

Follow the packet lifecycle manually: prepare a signed message, accept it once, replay the exact same packet, and run nonce verification.

All data and keys are temporary. No real message or permanent ledger entry is used.

04

Expired Digital Signature

See how the verification freshness window rejects an expired signed message.

05

Revoked Key Attack

See how a revoked signing key is rejected even if it was once trusted.

06

Ledger Tampering

Compare direct record modification with an attacker who also recalculates the local hash chain.
